# GTM metrics (weekly)

Keep a simple spreadsheet — no analytics product required for v1.

## North star (pick one primary)

**Weekly active routing:** users who run at least one successful `route_task` (proxy: GitHub issues + star velocity + self-reported Discord feedback until telemetry exists).

## Input metrics (you control)

| Metric | Target W1 | How |
|--------|-----------|-----|
| Launch posts published | 3 | HN, X, Discord |
| Demo video live | 1 | YouTube/X/GitHub README link |
| External links / mentions | 2 | Blogs, replies, tutorials |
| `@stack` tutorial | 1 | Gist or repo README |

## Output metrics

| Metric | Source |
|--------|--------|
| GitHub stars Δ | Insights |
| Forks / clone traffic | Insights |
| Issues / discussions | GitHub |
| Install friction reports | Issues containing "doctor", "hooks", "MCP" |

## Qualitative (gold)

- Someone quotes **token savings** back to you unprompted
- Team lead asks about **git sync** or **TEAM-WORKFLOW**
- Request for specific **@alias** (validates stack wedge strategy)

## Anti-vanity

Do not optimize for:
- README word count
- USP document revisions
- Feature count before next launch post

Review every Monday; one adjustment per week max.
